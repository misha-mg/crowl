# Фоновая работа Crowl на Mac Mini

Crowl запускается как пользовательский LaunchAgent. После установки бот остаётся доступен при закрытом или неактивном Terminal: сообщения приходят через long polling, а агентные процессы запускаются по запросу из Telegram.

Сервис работает, пока пользователь вошёл в macOS. Запуск до login, разблокировка FileVault и работа спящего/выключенного Mac не входят в пользовательский LaunchAgent. Mac Mini должен оставаться включённым и иметь интернет. Это соответствует модели [пользовательских агентов launchd](https://developer.apple.com/library/archive/documentation/MacOSX/Conceptual/BPSystemStartup/Chapters/CreatingLaunchdJobs.html).

## Установка и управление

В папке проекта `.crowl` уже должны быть заполнены Telegram-токен и числовой ID владельца в `.env`; Claude/Codex должны быть установлены и авторизованы под тем же пользователем macOS.

```bash
cd /path/to/project/.crowl
npm run doctor
npm run service:install
npm run service:status
```

Если Crowl уже работает в Terminal, сначала завершите именно этот процесс через Ctrl+C. Установщик проверяет блокировку проекта и бота и не запускает второй poller. Он не останавливает произвольные процессы автоматически.

После сообщения о запущенном процессе Terminal можно закрыть. Отправьте `/info` в Telegram и создайте/продолжите сессию для реальной проверки связи и авторизации. Статус launchctl подтверждает процесс, а не успешное обращение к Telegram или модели.

```bash
npm run service:stop       # Остановить, сохранив установку и историю
npm run service:start      # Запустить существующий сервис
npm run service:restart    # Остановить и загрузить актуальные пути/настройки
npm run service:uninstall  # Остановить и удалить LaunchAgent; данные остаются
```

Повторные `install` и `start` безопасны: работающий сервис не создаётся второй раз. Если plist отличается от актуальной конфигурации, `start` предлагает явный `restart`. Перемещение проекта или изменение пути Node.js требует перезапуска/переустановки соответствующего LaunchAgent.

Каждая `.crowl` имеет отдельный service label и plist. Токен не записывается в plist или аргументы процесса: сервис читает локальный `.env`. Устанавливается без sudo в `~/Library/LaunchAgents` и автоматически стартует после следующего login.

## Перезапуск и завершение

`KeepAlive=true` просит launchd поддерживать процесс, включая перезапуск после нормального завершения. Чтобы остановить сервис надолго, используйте `service:stop`/`uninstall`, которые выполняют `bootout`. При аварийных коротких запусках применяется интервал 30 секунд, чтобы не создавать частый цикл рестартов.

Crowl обрабатывает SIGTERM и завершает принадлежащие ему агентные процессы. launchd ждёт до 15 секунд перед принудительным завершением. Незавершённые задачи после аварии не исполняются повторно: их результат должен быть проверен перед продолжением очереди.

## Диагностика

`service:status` показывает установлен ли plist, загружен ли job, подтверждён ли работающий процесс, его PID и последний exit code, если launchctl их сообщает. Ошибка доступа к launchctl показывается отдельно; она не считается отсутствием сервиса.

Логи находятся внутри `.crowl/.data`:

- `service.log` — stdout процесса;
- `service-error.log` — ошибки запуска;
- `events.log` — технические события Crowl без полных промптов и токенов.

Файлы service.log/service-error.log ротируются при запуске Crowl и установке сервиса. Ротация использует копирование и обнуление исходного файла: открытый launchd дескриптор остаётся связан с активным логом. Хранится одна предыдущая копия `.1`.
