# Подключение второго проекта на Mac Mini

Каждый проект использует отдельный `.crowl`, `.env`, SQLite и Telegram-бот. Истории и задания не копируются между проектами. Общие локальные CLI и модель Whisper могут использоваться всеми экземплярами.

Из исходников или уже установленного Crowl:

```bash
npm run project:add -- /absolute/path/to/second-project
```

Папка проекта должна существовать. Установщик создаёт только `<проект>/.crowl`; существующий `.crowl`, даже пустой, никогда не перезаписывается. Бизнес-код проекта и его package.json не меняются. Символические ссылки в дистрибутиве не копируются.

Переносятся исходники и инструкции Crowl. `node_modules`, `.env`, `.data`, `.git`, локальные кеши и вложенные экземпляры исключаются. `.env` и `.env.example` создаются заново с пустыми токеном и user ID. Это защищает от случайного подключения второго проекта к первому боту. Копирование в проект внутри checkout Crowl поддерживается без рекурсивного самокопирования.

В новом экземпляре `MAX_CONCURRENT_SESSIONS=1`: все сессии доступны, но их задачи по умолчанию изменяют папку проекта последовательно. Значения 2–16 явно включают параллельное выполнение с общими файлами; внутри одной сессии FIFO сохраняется при любом лимите.

Установщик печатает команды для следующего шага:

1. Создайте второго бота у BotFather и запишите его токен в новый `.env`.
2. Напишите `/start` второму боту, затем запустите `npm run telegram:id` в его `.crowl` и заполните `TELEGRAM_USER_ID`.
3. Выполните `npm run doctor`, затем `npm start`. Runtime использует Node.js 24 без дополнительных пакетов; `npm ci` нужен для разработки и TypeScript-проверок.
4. После проверки остановите foreground и выполните `npm run service:install` для фонового запуска второго экземпляра.

Два проекта могут работать одновременно. У каждого отдельный label LaunchAgent. Один и тот же токен в двух проектах не поддерживается: локальная блокировка bot ID и конфликт polling предотвращают такое подключение.

Для сравнения исходной и установленной копии выполните `npm run app:version` в каждой. Одинаковые версия и fingerprint означают одинаковые учитываемые исходники и package.json; настройки и история в сравнение не входят. При обновлении сохраняйте локальные `.env` и `.data`, создавайте backup и перезапускайте именно нужный экземпляр. Установщик `project:add` предназначен для новой установки и не обновляет существующую `.crowl`.

## Проверка независимости

В первом чате попросите агента создать тестовый файл с одним содержимым, во втором — файл с другим. Через «Информация» проверьте разные директории. Затем переключите/закройте сессию в одном чате и убедитесь, что второй продолжает работать. Остановка одного LaunchAgent не должна останавливать другой.

Автотесты установщика проверяют исходные файлы, отсутствие перенесённых секретов, отказ от перезаписи, путь с пробелами, вложенную установку, исполнение установленного doctor из другого cwd, независимые SQLite и блокировки проектов. Интеграционная проверка с исполняемыми fixtures проверяет одновременное изменение файлов в двух проектах; это не заменяет живую приёмку второго Telegram-бота.
