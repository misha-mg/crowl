# Архитектура первой реализации Crowl

Дата: 28 октября 2026. Статус: реализовано; реальная Telegram-приёмка ожидает токена.

## Независимые экземпляры

Один процесс и LaunchAgent на `.crowl`, один бот и приватный чат владельца. Корень проекта вычисляется от исходного модуля конфигурации через realpath. При запуске требуется имя папки `.crowl`; это предотвращает случайную работу в родительском каталоге checkout разработчика. Состояние привязано к каноническому пути проекта, bot ID и user ID.

## Node.js 24 без runtime-пакетов

Вместо первоначальных grammY, zod и Vitest используются встроенные fetch/FormData, util.parseEnv, SQLite и node:test. TypeScript 5.9.3 и @types/node закреплены как devDependencies; npm lockfile сохранён. Node.js 24 исполняет используемый поднабор TypeScript без сборки. Установка через npm ci не запускает чужие install-скрипты runtime-зависимостей: их нет.

Причины: npm registry в текущем окружении недоступен (ENOTFOUND), но главное — прямой небольшой Bot API клиент позволяет явно сохранять inbox до продвижения offset. Отдельный фреймворк не нужен для десяти команд одного приватного бота. Валидация ограничена фиксированным набором настроек и входящих сообщений. Это осознанное изменение реализации, без изменения пользовательского контракта.

## Протоколы агентов

Codex 0.165.0: app-server stdio, initialize/initialized, thread/start|resume, turn/start|interrupt. Схемы получены локальной командой `codex app-server generate-ts`. Full запрашивает never + danger-full-access; Ask — untrusted + workspace-write. Действующая политика проверяется по ответу сервера до отправки промпта. Нативный ID сохраняется сразу после создания thread.

Claude Code 2.1.312: двунаправленный stream-json, control initialize/set_permission_mode/interrupt и can_use_tool. Формат сверялся с исходниками официального [Python Agent SDK](https://github.com/anthropics/claude-agent-sdk-python/tree/main/src/claude_agent_sdk/_internal). Это внутренний SDK-транспорт, а не обещание стабильности публичного CLI API; перед обновлением CLI выполняются probe, контрактные тесты и live smoke. Для CLI другой версии требуется повторная проверка. В коде нет копии агентного цикла или неофициальной авторизации.

Исходные точки протокола: [query.py](https://github.com/anthropics/claude-agent-sdk-python/blob/main/src/claude_agent_sdk/_internal/query.py), [subprocess_cli.py](https://github.com/anthropics/claude-agent-sdk-python/blob/main/src/claude_agent_sdk/_internal/transport/subprocess_cli.py). Контрактные сообщения закреплены исполняемым fixture и тестами обоих адаптеров. Текущая версия Claude реально ответила на handshake и приняла manual/bypassPermissions без вызова модели. Полный live smoke проверяется отдельно.

Каждый ход использует отдельный процесс с адресным resume; для Claude stdin остаётся открытым для control requests. Завершение хода учитывает результат и session_state_changed, чтобы не закрывать канал только на основании промежуточного result. Прогресс включает доступный пользователю текст и названия инструментов, без reasoning-блоков.

## Блокировки и восстановление

Вместо PID-файла удерживается SQLite write transaction в отдельной lock-БД. ОС освобождает блокировку после аварии; старый PID не используется для завершения процессов. Отдельные блокировки защищают путь проекта и bot ID на устройстве. Дочерние процессы создаются собственной process group; сигналы посылаются только группе ещё живого ChildProcess, а не прочитанному с диска PID.

Входящие сообщения, команды, задания и outbox транзакционны. Ответ на подтверждение передаётся процессу только после commit. Любой незавершённый run после рестарта становится unknown; очередь ставится на паузу. Отправка задания и произвольные изменения файлов не являются одной транзакцией, поэтому exactly-once исполнения не обещается. Неполученный результат не вызывает автоматического повтора.

## Голос и фон

Локальная цепочка OGG/Opus → FFmpeg → WAV → whisper.cpp, общая многоязычная модель base. Установка только явной командой voice:setup. Модель, Homebrew и FFmpeg не устанавливались скрыто при разработке.

Пользовательский LaunchAgent с абсолютными путями, без токена в plist, стартует после login. Текущая среда разработки не позволяет установку пользовательского сервиса за пределами workspace и запуск Codex app-server; эти ограничения отмечаются в отчёте и не обходятся изменением системных permissions.
